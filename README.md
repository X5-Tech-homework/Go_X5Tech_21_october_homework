## Обязательная часть

1. Завершите все три шага из `practice/README.md`: sentinel, wrapping, `SafeSend`, `SafeDispatch`.
2. Реализуйте `Error() string` у `*SendError`. Поля уже даны: `Channel string`, `Reason string`. Формат строки: `канал <Channel>: <Reason>`.
3. В `EmailNotifier.Send` после проверки пустого сообщения проверяйте `Address == ""`. В этом случае верните `*SendError` с `Channel: n.Channel`, `Reason: "не задан адрес"`.
4. Аналогично проверьте `DeviceID == ""` у push. Причина: `не задан device id`.
5. При любой ошибке историю не изменяйте. Если пусты и сообщение, и настройка, первым возвращается `ErrEmptyMessage`. Проверять настоящий формат адреса, пробелы или существование устройства не нужно.
6. В `cmd/notify/main.go` соберите четыре коротких запуска из следующего раздела. Решение о том, что вывести, принимайте в `main` через `errors.Is` и `errors.As`. Каналы и диспетчеры сами сообщения об ошибках в консоль не печатают.
7. Заполните `homework/МОЯ_РАБОТА.md`: назначение, команды запуска, результат четырёх случаев и различие двух диспетчеров.

`SendError` здесь хранит описание ошибки настройки, поэтому собственный `Unwrap` ей не нужен. Причина сохраняется в обёртке, которую создаёт диспетчер. В `*SendError` обращайтесь к полям только после успешного `errors.As`.

## Как проверить

Из папки `student`:

```bash
gofmt -w practice/tasks.go cmd/notify/main.go
go test -v ./practice -run TestHomework
go test ./...
go build ./...
go vet ./...
go run ./cmd/notify
gofmt -l practice/tasks.go cmd/notify/main.go
```

Последняя команда ничего не выводит, если форматирование в порядке. `go vet` выполняет статические проверки, а `gofmt` проверяет оформление. Конфигурации внешнего линтера в комплекте нет, устанавливать его для этого задания не нужно.

Перед сдачей убедитесь, что все тесты проходят, четыре случая запускаются, README заполнен, а репозиторий доступен преподавателю. Удалять или менять тесты, чтобы получить PASS, нельзя. Успешные тесты не заменяют разбор вашего `main` и README.

## Что будем оценивать

- Сохранены интерфейс и рабочее поведение сервиса из урока 4.
- Невалидная отправка не изменяет историю.
- `Dispatch` останавливается на первой ошибке и сохраняет причину.
- `SafeSend` возвращает обычную ошибку без замены, а панику преобразует в понятную ошибку.
- `SafeDispatch` действительно вызывает следующие каналы и возвращает все ошибки.
- `errors.Is` и `errors.As` используются по назначению.
- Четыре случая можно запустить одной командой, код оформлен и описан.
